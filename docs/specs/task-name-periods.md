# 任务名按日期分段

> 类型：参考
> 状态：已实现
> 适用版本：未发布
> 相关：../reference/data-model.md、../reference/tasks-and-intervals.md

## 目标

改名不再追溯覆盖历史：任务名按日期分段保存，网格与统计各自展示每个名称段，旧段的连续天数与完成率独立计算。

## 背景

现在 `tasks.name` 只有一份当前值，`updateTask` 原地更新；打卡只存 `task_id + date`。所以把「每天一个俯卧撑」改成「每天两个俯卧撑」后，网格行头、今日页、挂件、统计行会全部显示新名字，改名前的记录也被算进新名字的完成率。这与产品「历史不变」的原则冲突。

## 范围

- In-scope：
  - 新增 `task_name_periods` 表与迁移 005（含历史数据回填）
  - 改名从逻辑今天起生效，旧段截到昨天
  - 同名不操作；今天新建/未来启用/当天重复改名原地更新
  - 「只修正当前名字」入口，用于错别字，不拆分历史
  - 网格按名称段渲染，历史段默认折叠、可展开
  - 统计按名称段渲染，历史段默认折叠、可展开；旧段以段结束日为统计终点
  - 任务管理编辑弹窗展示名称历史
  - JSON v2 导出/导入，兼容 v1 导入
- Out-of-scope：
  - 补改历史生效日期（改名只能从今天起）
  - 合并不相邻的重复名称段
  - 今日页/挂件的名称分段展示（继续显示当前名字）
  - 值（value）语义调整

## 方案

### 数据

```sql
CREATE TABLE task_name_periods (
  id         TEXT PRIMARY KEY,
  task_id    TEXT NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  name       TEXT NOT NULL,
  start_date TEXT NOT NULL,
  end_date   TEXT,
  CHECK (end_date IS NULL OR end_date >= start_date)
);
CREATE UNIQUE INDEX idx_name_periods_task_start
  ON task_name_periods(task_id, start_date);
```

- 迁移回填：每个任务一段，起点取最早区间启用日；没有区间时取创建日。
- `tasks.name` 保留为当前名字缓存；有名称段时以最新段为准。

### 改名

`renameTask(db, id, newName, today, mode)`：

| 情况 | 行为 |
|---|---|
| 同名 | 不操作 |
| `mode = "rewrite-current"` | 改写当前段名字，不新增段 |
| 当前段 `start >= today` | 原地改 |
| 任务创建日 = 今天 | 原地改 |
| 其他 | 当前段 `end_date = today - 1`，新段从 `today` 开始 |

`today` 一律使用 `logicalToday`。

### 展示

- 网格一行 = 一个名称段；当前段始终显示，历史段默认折叠。
- 当前段名字右侧显示紧凑的 `▸ N` 按钮（悬停/读屏给出「N 个曾用名」），展开后历史段置灰并显示日期范围。
- 历史段在自身日期范围外不显示格子；分组计数按任务去重；拖拽按任务去重。
- 统计一行 = 一个名称段；当前段以今天为终点，历史段以段结束日为终点；30 天窗口不越过段起点。
- 统计列头改为「连续 / 完成率」，底部说明补充分段口径。

### 导入导出

- JSON v2 新增 `namePeriods`。
- v1 导入时按最早区间启用日合成一段。
- 按 id upsert，保持幂等。

- [x] 迁移后每个既有任务都有且仅有一个覆盖其历史的名称段。
- [x] 改名后旧段在昨天结束，新段从今天开始；同名不改；当天重复改名仍只有一段。
- [x] 新建任务、未来启用任务改名不产生多余历史段。
- [x] 「只修正当前名字」不改动段边界。
- [x] 网格默认只显示当前名称段；展开后旧段显示旧名字与日期范围，且范围外格子不可点。

- [x] 统计默认只显示当前名称段；展开后旧段使用旧名字，连续天数与完成率只统计该段日期。

- 假设：改名入口只有任务管理编辑弹窗。
- 假设：名称历史折叠状态不持久化，重启后恢复折叠。
- 假设：网格与统计的旧段行仍可查看/编辑对应日期的打卡。
