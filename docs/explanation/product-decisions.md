# 产品决策

> 类型：解释
> 状态：稳定
> 适用版本：v0.1.9+
> 相关：reference/checkins.md、reference/tasks-and-intervals.md、explanation/adr/0002-interval-every-days.md

本文解释 DailyTask 为什么是现在这个样子。具体规则查 `reference/`。

---

## 1. 要解决的问题

原来用 Excel 做习惯打卡：

- 每改一次任务，就要复制一张表头
- 表头一改，历史记录跟着漂移
- 列宽、冻结窗口、缩放每次都要重设

DailyTask 的目标是把「历史不变」和「今天好用」分开。

## 2. 为什么没有「表头」

Excel 的表头同时承担：

- 当前有哪些任务
- 历史某天有哪些任务

这两个需求会冲突。DailyTask 把它拆成：

- 任务 = 名称 + 类型 + 排序
- 启用区间 = 任务在某段时间是否适用

新增、停用、重新启用都只追加区间；历史打卡永远挂在原任务上。

代价是 UI 要解释「区间」和「停用/重新启用」。

## 3. 为什么日期做列、任务做行

- 习惯是连续的，横向时间轴更符合直觉
- 任务数量少（5–15），日期数量多（数百到上千）
- 行固定、列滚动，任务名始终可见

代价是横向虚拟化和 sticky 表头更复杂。

## 4. 为什么挂件和主窗并存

- 挂件负责「快速看一眼 + 打勾」
- 主窗负责「管理 + 回看 + 编辑」

两者不互斥，挂件独立置顶，主窗隐藏到托盘。

## 5. 为什么只有三种状态

早期有 `recorded`（只记录）。实际使用中：

- 用户会把它当成第四种勾选状态
- 统计多一个分支
- 值本来就可以附加在任意状态上

v0.1.6 移除 `recorded`：没有判定时写值自动记为 `done`。代价是无法再表达「有值但未判定」。

## 6. 为什么值不是状态

值回答「做了多少」，状态回答「做没做」。两者正交：

- `done` + `30min`
- `missed` + `0`
- `skipped` + 空

把值提升为状态会让统计和 UI 都复杂。

## 7. 为什么自动结算只投影

如果启动时把过去空白批量写成 `missed`：

- 会写几百行
- 用户改「自动结算」设置后历史被永久污染

所以只读时投影，用户点击后才落库。

## 8. 为什么每 N 天挂在区间上

- 任务停用/重新启用后，历史周期不能被后来修改
- 每段独立锚点更符合「这段从哪天开始」的心智

代价是任务管理只展示最新一段，历史段只读。

## 9. 为什么删除要确认令牌

删除入口多，单靠组件封装容易被绕过。store 删除要求品牌类型，页面直接调用编译失败。

详见 [ADR 0004](adr/0004-confirmed-deletes.md)。

## 10. 为什么默认跟随系统语言

- 英文 Windows 用户首次启动不应该看到中文
- 中文 Windows 用户不需要手动设置
- 只有中英两套完整字典，其他语言回退中文

## 11. 为什么任务截止日期复用区间 end

- 区间 `end` 本来就表达「这段启用到哪天」，和截止日期是同一件事
- 复用后历史、统计、任务表、JSON 导入导出都不需要新字段或迁移
- 截止日次日任务自动不再出现，符合「到期即结束」的心智
- 需要继续跟踪时，用「重新启用」追加新段，历史不变

## 12. 为什么任务名按日期分段

Excel 最痛的问题是「表头一改，历史记录跟着漂移」。启用区间解决了「哪些天有这个任务」，但任务名仍然只有一份当前值：

- 把「每天一个俯卧撑」改成「每天两个俯卧撑」，过去一年的格子会全部显示新名字
- 旧日子的完成率会被算进新目标的统计
- 用户无法回答「去年我坚持的是哪个目标」

所以任务名也按日期分段：改名从今天起生效，旧段截到昨天。网格和统计按段拆行，旧段用自己的名字、连续天数和完成率。错别字是例外：编辑弹窗提供「只修正当前名字」，原地改写当前段，不制造无意义的历史。

代价是网格和统计的行数会随改名次数增加；用「历史段默认折叠」压住视觉噪音。改名只能从今天起，不允许补改生效日，是为了避免把已经写进历史的打卡重新归因。

## 13. 明确不做

- 云同步 / 账号
- 系统通知
- 热力图 / 全局折线
- 格子按量统计
- 移动端
- 更新降级
