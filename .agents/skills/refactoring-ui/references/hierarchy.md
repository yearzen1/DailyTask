# 视觉层级（Hierarchy）

## 一句话

界面"乱"的根因，是每个元素都在争夺同一份注意力；让次要信息主动退后，比让重要信息往前挤更有效。

## 三个可调的工具

| 工具 | 适用 | 注意 |
|---|---|---|
| 字号 | 跨度大的层级（页面标题 vs 正文） | 过度依赖会让主内容过大、次要内容过小 |
| 字重 | 相邻层级的强调 | 全站 2 种就够：400/500 与 600/700；不用 < 400 |
| 颜色（对比度） | 弱化辅助信息 | 白底上用灰；**彩色底上不用灰** |

推荐组合：文字最多 3 个颜色（深色主 / 中灰次 / 浅灰三级），2–3 种字号，2 种字重。

## 彩色背景上的文字

- 灰字在彩色底上会显脏；半透明白会让文字发闷、像禁用态，还会透出背景图案。
- 正确做法：取背景同色相，手动降低对比度（提高明度或降低饱和度），直到"看着舒服"。
- 反过来做无障碍更省事：**浅色底 + 深色文字**，比深色底 + 白字容易达到 4.5:1，也不抢戏。

## 用弱化来强调

- 元素不够突出时，先问"谁在跟它抢"，然后把那些降下去：非激活导航项换更柔的颜色、侧边栏去掉背景色让内容直接落在页面底。
- 弱化永远比加装饰便宜：不引入新元素、不加新颜色、不改布局。

## 标签（label）处理

按顺序尝试，能停在前一步就别继续：

1. **删掉标签**：邮箱、电话、价格这类靠格式能认出来的数据不需要标签。
2. **合并标签与值**：`库存：12` → `还剩 12 件`；`卧室：3` → `3 间卧室`。
3. **保留但弱化**：多条同类数据需要快速扫读时（仪表盘），标签用小字号 + 低对比 + 轻字重。
4. **强调标签**：只有用户明确在"找标签"时（技术规格页找 depth、7.6mm），标签用深色，值稍浅。

## 视觉层级 ≠ 文档层级

- `h1`、`h2` 只决定语义，不决定字号。应用界面里 `Manage Account` 这类区块标题常常更像标签。
- 语义必要的标题可以视觉隐藏（`sr-only`），让内容自己说话。
- 选标签按语义，定样式按视觉需要，两者解耦。

## 字重与对比度的配重

- 面积决定视觉重量：粗体、实心图标覆盖像素多，显得更重。
- 图标比文字重 → 给图标更柔的颜色降对比度（无法改"字重"，就改对比度）。
- 细边框太弱但加深又显生硬 → 把边框加粗 1px，保留柔和色。
- 反方向同样成立：低对比元素显得太飘时，加字重比加颜色更轻。

## 操作金字塔

大多数页面只有 1 个真正的主要操作：

| 层级 | 样式 | 例子 |
|---|---|---|
| Primary | 实心、高对比背景 | 保存、提交、下一步 |
| Secondary | 描边，或低对比浅底 | 取消、预览、导出 |
| Tertiary | 文字链接样式 | 删除、重置、了解更多 |

- 破坏性操作不等于大红粗：不是页面主操作时按 secondary/tertiary 处理，把强烈样式留给确认弹窗（那一步它才是 primary）。
- 三层之上不要再加第四层；需要第四层说明页面该拆了。

## 自检

- 眯眼或转灰度看截图，最重要元素是否仍然最先跳出来？
- 是否存在两个元素的重要性肉眼无法区分？
- 是否有元素只是因为"语义重要"而样式过重（h1、必需字段、破坏性操作）？
