# 色彩（Color）

## 用 HSL 思考

- hex/RGB 里，肉眼几乎相同的两个颜色在代码里毫无关联，无法推理。
- HSL：**色相**（0 红 / 120 绿 / 240 蓝）、**饱和度**（0% 灰 → 100% 浓烈）、**明度**（0% 黑 / 50% 纯色 / 100% 白）。
- 别混淆 HSL 与 HSB：HSB 亮度 100% 只在饱和度为 0% 时才是白；网页只用 HSL。

## 你需要多少颜色

| 类别 | 用途 | 色阶数 |
|---|---|---|
| 灰色 | 文字、背景、面板、表单、边框（界面里绝大多数东西） | 8–10 |
| 主色 | 主要操作、激活态、品牌识别 | 5–10 |
| 强调色 | 新功能、状态语义（红/黄/绿）、分类与图表 | 每个 5–10 |

复杂界面出现 10 种颜色 × 5–10 色阶是正常的。5 个"完美配色"什么都做不出来。

## 构建 9 级色阶（100–900）

```
100 最浅（染色背景） → 500 基色（按钮底） → 900 最深（文字）
```

步骤：

1. **选基色**：一个直接能当按钮背景的色阶。不要套"50% 明度"规则，颜色各异，看眼睛。
2. **定两端**：900 按"最深文字"挑；100 按"最浅染色背景"挑（用一个提示框组件同时定这两端）。
3. **补中间**：先 700 和 300（视觉上正好居中），再 800/600/400/200。
4. **微调**：用起来一定会想调某个色阶的饱和度，相信眼睛。但不要频繁增加新色阶——不限量就等于没有体系。

参考明度（彩色）：`96 90 82 72 62 52 42 32 20`；灰色：`95 90 82 72 60 48 38 28 18`。

### 饱和度补偿

HSL 里明度越接近 0% 或 100%，饱和度的作用越弱 —— 同样的饱和度，50% 明度时比 90% 明度更有色彩感。所以：

- 明度每偏离 50% 十个点，饱和度 +5–8；
- 极浅/极深档再加 15–25，否则色阶发灰、显脏。

### 用色相调亮度

色相本身有感知亮度差异（黄最亮，蓝最暗；局部最低点在红绿蓝，最高点在黄青品红）。

- 变亮 → 朝 60° / 180° / 300° 转；变暗 → 朝 0° / 120° / 240° 转。
- 单次 **≤ 20–30°**，否则看起来变成另一种颜色。
- 典型用法：黄色系做深色阶时向橙色偏，避免变褐；也可与明度调整各承担一半。

## 灰色不是纯灰

- 纯灰饱和度 0%，但让人舒服的界面灰通常带饱和度，这就是冷暖灰。
- 冷灰：加蓝（hue 200–220）；暖灰：加黄/橙（hue 30–50）。
- 浅档和深档要同步加饱和度，否则中间档与两端色温断层、显灰白。
- 加多少由气质决定：想轻微偏色就加一点，想强烈风格化就加足。

## 无障碍不等于难看

- WCAG：正文（<18px）对比度 ≥ **4.5:1**，大字 ≥ **3:1**。
- **反转对比关系**：彩色背景 + 白字往往要深到成为页面焦点才能达标。改用浅色背景 + 深色文字，颜色还在，但不再抢戏。
- **旋转色相达标**：深色面板里的次要文字，只调明度会一路逼近纯白；把色相朝亮色（青/品红/黄）旋转，可在保住色彩的同时提高对比度。

## 不要只靠颜色

- 状态不能只用红/绿表达：配图标（↑↓、✓✗）或文字。
- 图表多条线：靠**明暗对比**区分，比靠不同色相更可靠（色盲用户更容易分辨深浅）。
- 原则：颜色只能强化设计已经表达的信息，绝不能是唯一表达方式。

## 自检

- 是否所有颜色都来自固定色阶，没有 `lighten()/darken()` 现算值？
- 浅档/深档的饱和度是否补偿过？
- 灰色是否带轻微冷暖倾向且全档一致？
- 正文对比度是否 ≥ 4.5:1，彩色底是否用浅底深字？
- 状态与图表是否在灰度下仍可区分？
